# Supabase для Финни — схема готова, НЕ применена

`schema.sql` — полная схема (семьи, ребёнок/родитель, состояние игры, мечта, заказы и торг,
журнал реальных денег, мост игровых ₪, настройки, лимиты). Приложение сейчас её НЕ использует:
всё хранится в localStorage.

Ключевые гарантии (проверены на реальном Postgres через PGlite):
- журнал только дописывается (UPDATE/DELETE/TRUNCATE запрещены), прямой INSERT закрыт;
  деньги попадают в него только через функции `job_confirm`, `ledger_add`, `bridge_apply`;
- ребёнок не может подтвердить заказ, записать выплату, зачесть мост или видеть настройки (хэш PIN);
- торг строго по очереди, не более 4 встречных цен, одна выплата за заказ;
- мост «игровой ₪ → реальный» выключен по умолчанию (курс 0, лимит 0).

Проверка: `cd supabase/tests && npm i @electric-sql/pglite && node schema.test.mjs`
(поправьте путь к schema.sql в начале скрипта).

Когда будете выкатывать: новый проект → SQL editor/`supabase db push` → включить Auth
(родитель — email, ребёнок — отдельный пользователь семьи) → заменить `lib/real.ts` вызовами
RPC-функций (`job_propose`, `job_negotiate`, `job_claim`, `job_confirm`, …).
